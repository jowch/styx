## Cursor Cloud specific instructions

- **Runtime:** Julia 1.11+ is installed via `juliaup` at `~/.juliaup/bin` (`~/.bashrc`/`~/.profile` add it to `PATH`; use the absolute path in non-login shells). The workspace holds sibling checkouts `/agent/repos/plutomcp.jl` and `/agent/repos/styx`.
- **Plugin Julia env:** bootstrap with `PLUTOMCP_SOURCE=/agent/repos/plutomcp.jl bash scripts/ensure-julia-env.sh`. `PLUTOMCP_SOURCE` is **required** on Linux: the script's sibling auto-dev lookup expects `../PlutoMCP.jl` (capitalized), but the local checkout is lowercase `plutomcp.jl`, so without it the script falls back to fetching the fork from GitHub instead of dev-linking the local copy. The script writes a `.julia-env-instantiated` marker and is idempotent (pass `PLUTOMCP_ENV_FORCE=1` to force re-resolve).
- **Eval harness (`eval/`) JSON3 caveat:** `run_reference.jl`/`EvalShared.jl` import `JSON3` while activating `PLUTOMCP_ROOT`, but PlutoMCP uses `JSON.jl` and does **not** depend on `JSON3`. Loading `JSON3` from the shared depot env against PlutoMCP's pinned `Parsers` fails with `UndefVarError: typeparser not defined in Parsers`. Fix: point `PLUTOMCP_ROOT` at a dedicated combined env that resolves `PlutoMCP` + `JSON3` + `HTTP` together (this downgrades `Parsers` to a mutually compatible version). Create once, then run:
  - `julia --project=$HOME/.styx-eval-env -e 'using Pkg; Pkg.develop(path="/agent/repos/plutomcp.jl"); Pkg.add(["JSON3","HTTP","UUIDs"])'`
  - `cd eval && PLUTOMCP_ROOT=$HOME/.styx-eval-env julia run_reference.jl --all --strict-trace` (all 4 scenarios pass; set `EVAL_HEALTH_TIMEOUT=180` on a cold precompile).
- **Run the stack for manual checks:** start `PlutoMCP.serve(...)` from the `plutomcp.jl` checkout (see that repo's cloud section) — default local ports are often Pluto `:1234` and MCP `:2346`, but bound sessions use dynamic ports from `pluto_session_status`. With `require_secret_for_access=false`, open a notebook at `<pluto_url>/edit?id=<notebook_id>`; MCP edits (`add_cell`/`edit_cell` → `submit_changes`) reactively update the open browser over the websocket.
